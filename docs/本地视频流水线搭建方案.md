# 本地视频流水线搭建方案 —— videoforge

> 目标：把「输入一个主题，产出一条科普/历史短视频」的过程标准化、固化到本地，形成一条可复用流水线。
> 文案、文生图、语音合成统一走火山引擎方舟 Agent Plan，模型 ID 集中在配置文件中替换。

> **现状声明**：本文描述的是当前代码实现。六个 CLI 命令均有单元测试（Ark HTTP 请求全部经 mock），
> 但使用真实密钥与真实模型的端到端冒烟**尚未执行**；首次全链路验证流程见
> [操作者使用说明](docs/guides/operator-guide.md) 第 5 章。不要把本文能力描述理解为已验收。

## 1. 总体架构

```
┌─────────────────────────────────────────────────────────────────┐
│ 编排层：Trae / OpenClaw 等 harness 中的 agent                      │
│ 按 .trae/skills/vf-*/SKILL.md 逐步驱动（也可手动执行同样的命令）      │
└──────────────────────────┬──────────────────────────────────────┘
                           │ 逐条调用、检查退出码与 stdout JSON
┌──────────────────────────▼──────────────────────────────────────┐
│ CLI（apps/cli，pnpm --filter @videoforge/cli start <命令>）        │
│ copy:gen → image:gen → tts:gen → storyboard:gen → render → compose│
└──────┬───────────────────┬───────────────────┬──────────────────┘
       │                   │                   │
┌──────▼───────┐   ┌───────▼────────┐   ┌──────▼───────┐   ┌─────────┐
│ Ark 文案模型  │   │ Ark 文生图      │   │ openspeech   │   │ 本地积木 │
│ chat         │   │ seedream 2K png│   │ TTS mp3      │   │ ffprobe  │
│ completions  │   │                │   │ (NDJSON 流)  │   │ Playwright│
└──────────────┘   └────────────────┘   └──────────────┘   │ ffmpeg   │
                                                           └─────────┘
产物：<storage_root>/workspace/<工作区名>/{copy.json, images/, audio/, timeline.json, build/, final.mp4}
监控：Web 控制台 /workspaces 只读展示上述物料与成片（不参与编排、不保存审核结论）
```

**分层职责**

| 层       | 实现                                             | 职责                                       | 可替换点                                                      |
| -------- | ------------------------------------------------ | ------------------------------------------ | ------------------------------------------------------------- |
| 编排层   | `.trae/skills/` 四个 SKILL.md                    | 步骤拆解、审核点提示、失败排查指引         | 薄封装，不含能力本身                                          |
| 文案层   | CLI `copy:gen` → `arkChatCompletion`             | 主题 → 4-8 个分镜的口播文案与文生图提示词  | 模型 ID 在配置 `chat_model`                                   |
| 资产层   | CLI `image:gen` / `tts:gen` → Ark 客户端         | 分镜提示词 → png；口播文案 → mp3           | 模型 ID 在配置 `image_model` / `tts_speaker`                  |
| 时间轴层 | CLI `storyboard:gen` → ffprobe + `buildTimeline` | 实测每段音频时长，生成连续时间轴           | 尾部停顿当前固定 500ms                                        |
| 渲染层   | CLI `render` → Playwright + template-sdk         | HTML 场景（底图+标题+旁白+进度条）逐帧截图 | 场景美术在 `template-sdk/minimal-scene.ts`                    |
| 合成层   | CLI `compose` → ffmpeg                           | concat 拼接语音，与帧序列合成 mp4          | 帧率/分辨率在 Profile（`LANDSCAPE_1080P` / `PORTRAIT_1080P`） |

**核心机制：音画自动对齐。** 手填时长必然漂移，所以流水线反过来：先合成全部旁白 → `ffprobe` 实测每段时长 →
`buildTimeline` 生成连续时间轴 → 每段画面时长 = 该段音频实测时长 → 合成时 ffmpeg `-shortest` 按音频截断。
画面与语音天然严丝合缝。注意：`timeline.json` 的 `totalMs` 含 500ms 尾部余量，该余量**不会**出现在成片里，
成片时长 = 语音总长，验收时按 ±1 秒容差理解。

## 2. 环境依赖

| 依赖                | 版本       | 用途                         | 说明                                                    |
| ------------------- | ---------- | ---------------------------- | ------------------------------------------------------- |
| Node.js             | ≥ 20       | CLI / API / 渲染             | 由 `pnpm run doctor` 校验                               |
| pnpm                | 10.x       | monorepo 包管理              | 见根 `package.json` 的 packageManager                   |
| Python              | ≥ 3.10     | Edge TTS 声音目录适配器      | 依赖装入 `adapters-python/.venv`；与 Ark TTS 流水线无关 |
| ffmpeg / ffprobe    | ≥ 5        | 测时长、拼音频、合成视频     | 可执行名或完整路径在 `tools.*_path` 配置                |
| Chromium / Chrome   | 任意近期版 | 无头逐帧截图                 | `tools.chromium_path` 指定，留空则由 Playwright 管理    |
| 火山方舟 Agent Plan | —          | 文案 / 文生图 / TTS 模型供给 | API Key 放 `.env.local`，模型 ID 放 `system.local.yaml` |

```powershell
pnpm install
pnpm run doctor   # 逐项校验上述本机依赖
```

## 3. 模型与配置（核心诉求）

模型选择集中在 `config/default.yaml` 的 `engines.endpoints.ark` 段，本机覆盖写在
`config/system.local.yaml`（已 gitignore），密钥只放仓库根目录 `.env.local`。

| 配置项            | 默认值                                                            | 说明                                                                                  |
| ----------------- | ----------------------------------------------------------------- | ------------------------------------------------------------------------------------- |
| `base_url`        | `https://ark.cn-beijing.volces.com/api/plan/v3`                   | Agent Plan 专用路径，**严禁改为** **`/api/v3`（会产生额外费用）**                     |
| `chat_model`      | `PLEASE_FILL_CHAT_MODEL_ID`                                       | 语言模型 ID，**占位值，必须在 system.local.yaml 填真实 ID**，否则 `copy:gen` 拒绝执行 |
| `image_model`     | `doubao-seedream-5-0-pro-260628`                                  | 文生图模型，出图尺寸固定 2K                                                           |
| `tts_base_url`    | `https://openspeech.bytedance.com/api/v3/plan/tts/unidirectional` | TTS 服务地址（openspeech，与 base\_url 不同源）                                       |
| `tts_resource_id` | `seed-tts-2.0`                                                    | TTS 资源 ID                                                                           |
| `tts_speaker`     | `zh_female_vv_uranus_bigtts`                                      | 默认说话人，可被 CLI `--speaker` 覆盖；取值以火山控制台语音列表为准                   |

`.env.local` 内容（已 gitignore；密钥不得写入 YAML、日志、manifest、测试快照或任何会被提交的文件）：

```text
ARK_API_KEY=<你的火山方舟 API Key>
```

另有独立的 Edge TTS 能力（`adapters-python` + 服务端 voice-service）：为控制台「声音目录 / 试听」页面服务，
与 Ark TTS 流水线互不依赖。

## 4. 中间契约与产物布局

### 4.1 copy.json（贯穿全流程的契约）

`copy:gen` 产出、后续命令消费并回填，UTF-8、2 空格缩进，由 zod schema 校验
（`apps/server/src/pipeline/copy-contract.ts`）：

```json
{
  "topic": "主题（来自 --topic）",
  "style": "风格（来自 --style，默认科普）",
  "title": "视频标题（模型生成）",
  "scenes": [
    {
      "sceneId": "s1",
      "title": "场景标题",
      "narration": "口播文案",
      "imagePrompt": "文生图提示词",
      "imagePath": "由 image:gen 回填",
      "audioPath": "由 tts:gen 回填"
    }
  ]
}
```

### 4.2 timeline.json（storyboard:gen 产物）

`{"entries":[{"sceneId":"s1","durationMs":3520,"startMs":0,"endMs":3520}, ...], "totalMs":N}`，
`durationMs` 为 ffprobe 实测，`totalMs` = 各场景时长之和 + 500ms 尾部余量。

### 4.3 工作区目录布局

```
<storage_root>/workspace/<工作区名>/        # 建议命名「日期-主题」，如 2026-10-08-黑洞
├── copy.json                              # 文案契约（imagePath/audioPath 逐步回填）
├── images/<sceneId>.png                   # 每场景一张 2K 配图
├── audio/<sceneId>.mp3                    # 每场景一条口播
├── timeline.json                          # 分镜时间轴
├── build/
│   ├── render/<landscape|portrait>/frames/00000001.png…   # 跨场景连续编号帧
│   └── compose/<landscape|portrait>/{voice-all.mp3, ffmpeg.log}
└── final.mp4                              # 最终成片（必须叫这个名字，Web 列表才识别为已生成）
```

放在 `<storage_root>/workspace/` 下是**约定而非强制**：CLI 接受任意显式路径，
但只有该目录下的工作区才会出现在 Web 控制台的工作区页面。

## 5. 运行与产出

```powershell
# 0. 准备：.env.local 写 ARK_API_KEY；system.local.yaml 填 chat_model；pnpm run doctor 通过
$ws = "<storage_root>\workspace\2026-10-08-黑洞"

pnpm --filter @videoforge/cli start copy:gen --topic "黑洞是什么" --style "科普" --out "$ws\copy.json"
# 审核点 1：人工检查 copy.json 的标题、口播与分镜
pnpm --filter @videoforge/cli start image:gen --copy "$ws\copy.json"
# 审核点 2：人工检查 images\ 下配图，可改 imagePrompt 后重跑本步
pnpm --filter @videoforge/cli start tts:gen --copy "$ws\copy.json"
pnpm --filter @videoforge/cli start storyboard:gen --copy "$ws\copy.json" --out "$ws\timeline.json"
pnpm --filter @videoforge/cli start render --copy "$ws\copy.json" --timeline "$ws\timeline.json"
pnpm --filter @videoforge/cli start compose --copy "$ws\copy.json" --out "$ws\final.mp4"
```

**Web 监控**（两个独立终端）：

```powershell
pnpm run server:dev   # API，监听 127.0.0.1:<配置端口>
pnpm run web:dev      # 控制台，打开 http://localhost:5173/workspaces
```

工作区列表展示「文案 / 成片」状态，详情页展示分镜卡片（配图、口播文案、音频试听）并可直接播放 `final.mp4`。
页面为只读监控，不保存任何审核结论。

## 6. Trae skills（harness 编排入口）

`.trae/skills/` 下四个 skill 是上述命令的薄封装，供 harness 中的 agent 按序调用（A 方案：harness 主导编排，
skill 只提供步骤指导，能力全部来自 CLI）：

| skill           | 包装的命令                              | 触发场景             |
| --------------- | --------------------------------------- | -------------------- |
| `vf-copywriter` | `copy:gen`                              | 用户给出视频主题     |
| `vf-image-gen`  | `image:gen`                             | 文案已审核，需要配图 |
| `vf-tts`        | `tts:gen`                               | 配图就绪，需要配音   |
| `vf-storyboard` | `storyboard:gen` → `render` → `compose` | 配音完成，需要出片   |

每个 SKILL.md 含前置条件、命令示例、契约说明、按错误码的失败排查与产物位置。

## 7. 错误码速查

| 错误码                     | 常见原因                                                                                     |
| -------------------------- | -------------------------------------------------------------------------------------------- |
| `CONFIG_INVALID`           | 缺 `ARK_API_KEY`；`chat_model` 仍为占位值；缺必填参数；场景缺 `audioPath`；`--profile` 非法  |
| `ADAPTER_PROTOCOL_INVALID` | 文案模型未输出合法 JSON；copy.json / timeline.json 解析失败或结构非法；timeline 引用未知场景 |
| `ADAPTER_FAILED`           | Ark HTTP 非 2xx；TTS 响应不含音频数据；ffprobe 输出非法                                      |
| `TOOL_UNAVAILABLE`         | ffmpeg / ffprobe 启动失败或退出码非 0（合成诊断见 `build/compose/<profile>/ffmpeg.log`）     |
| `UNEXPECTED_ERROR`         | 未归类异常（如 Chromium 启动失败、磁盘写入失败）                                             |

## 8. 仓库结构速览

```
videoforge/
├── apps/
│   ├── cli/          # doctor + 六个流水线命令（tsx 直跑，无构建步骤）
│   ├── server/       # Fastify API + 领域模块（shared/db/pipeline/renderer/template-sdk）
│   ├── web/          # Vue 3 控制台（项目/声音/工作区页面）
│   └── worker/       # Worker 基础入口（尚未接入调度循环）
├── adapters-python/  # Edge TTS 语音适配器（JSON CLI 协议，UTF-8）
├── config/           # default.yaml + system.local(.example).yaml + 输出 Profile
├── tests/            # Vitest 单元与集成测试（26 个文件 / 82 个用例）
├── .trae/skills/     # 四个流水线 skill（harness 编排入口）
└── docs/             # guides（开发者/操作者说明）与 superpowers 计划文档
```

TypeScript 严格模式 + ESM + NodeNext；跨应用依赖 `workspace:*`，worker/cli 通过
`@videoforge/server/src/...` 子路径复用服务端模块。
