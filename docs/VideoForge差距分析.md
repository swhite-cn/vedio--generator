# VideoForge 与参考成片的差距分析

> 分析对象：`D:\07_ai-workspace\01_vedio_generator`（下称 VideoForge）
> 对标样本：《这家硅谷聚变公司把水银轰成黄金》1080P / 4:51，实测数据见《科普视频拆解与套用模板.md》
> 本文为只读分析，未修改任何代码。

---

## 一、结论

VideoForge 的技术方向是对的：**HTML + GSAP 确定性寻帧 → Playwright 逐帧截图 → ffmpeg 合成**，这恰好就是参考片那种"排版型动效"的正确底座。

差距不在技术栈，而在**粒度**：

- VideoForge 现在：一场景 = 一段口播（60–120 字）+ 一张 AI 图 + 一个 8–12 秒动画
- 参考片实际：一句话 = 一个镜头，平均 3.7 秒一次画面变化

两者差 3–6 倍。这不是调参能补的，需要新增一层数据结构。

---

## 二、现状盘点

### 2.1 七阶段实际行为

| 环节 | 现在的做法 | 代码位置 |
|---|---|---|
| copy | 生成 4–8 个场景，每场景口播 60–120 字，附一条 imagePrompt | `config/prompts/default/copy-system.txt` |
| image | 每场景调用一次 Seedream 2K 文生图，无参考图、无 seed、无负面词；只追加一句"不要出现文字"的后缀 | `packages/pipeline/src/image-generate.ts`、`ark-client.ts` |
| scene | LLM 一次性生成整场 HTML + CSS + JS，GSAP 时间轴写死 8–12 秒 | `config/prompts/default/scene-system.txt` |
| tts | 逐场景整段合成，请求体不包含任何时间戳参数 | `packages/pipeline/src/ark-client.ts` |
| storyboard | ffprobe 实测音频时长，串成连续时间轴，末尾加停顿 | `packages/pipeline/src/timeline.ts` |
| render | 逐帧 `progress = 当前时刻 / 场景时长`，再 `seek(progress × 时间轴时长)` | `packages/renderer/src/render.ts` |
| compose | 帧序列 + 拼接后的旁白音频；BGM 引擎支持但工具未暴露 | `packages/pipeline/src/compose.ts`、`apps/server/src/agent/tools/stage-tools.ts` |

### 2.2 换算成画面节奏

- 每场景口播 60–120 字 ÷ 6.7 字/秒 ≈ **9–18 秒**
- 全片只有 **4–8 个镜头**
- 参考片：78 次画面变化、平均 3.7 秒一次、整幅换镜 6–7 秒、98 句旁白每句 2.9 秒

**一个 scene 的时长，等于参考片的 3–6 个镜头。**

## 三、六项硬差距

| 维度 | 参考片 | 当前流水线 | 差距性质 |
|---|---|---|---|
| 分镜粒度 | 39–78 次画面变化，一句一镜 | 一场景一镜，9–18 秒 | 数据结构缺失（没有 shot 层） |
| 字幕 | 逐句硬字幕，每句 2–3 秒，白字黑边 | 整段口播塞进底部字幕条 | 无时间戳，无法逐句 |
| 版式 | 数据卡 / 引语卡 / 对比条 / 进度环 / 章节角标 / 来源标签 / 关键词块 共 7 类组件 | 一张底图 + 大标题 + 字幕条 | 无组件库，全靠 LLM 每次现编 |
| 素材 | 手绘插画 + 实拍 + 档案照片 + 3D 渲染 + 符号化图形 | 仅一种：AI 文生图 | 素材类型单一 |
| 动效节奏 | 硬切为主；关键词整体上屏、下划线扫入、数字计数滚动 | 单个 8–12 秒时间轴被拉伸到实际时长 | 动效速度不可控 |
| 可信度 | 每处数据带来源标签，且口头免责 | 契约里没有来源 / 免责字段 | 概念缺失 |

### 3.1 两个隐藏但致命的技术点

**（1）时间轴被拉伸**

`render.ts` 把 8–12 秒的 GSAP 时间轴按进度映射到实际 15–20 秒：

```
progress = (帧号 / fps × 1000) / 场景时长
timelineTime = progress × 时间轴时长
```

场景越长，动画越慢。最终观感是"PPT 缓慢飘"。参考片的每个动效是固定时长（0.3–0.8 秒），与口播长度无关。

**（2）风格无法跨镜头一致**

每个场景独立调文生图，只有一句"不要出现文字"的后缀。参考片全片保持"质子=红球、中子=灰球、水银=银球、金=金球"的符号系统——这需要跨镜头资产一致性，当前架构无法做到。

## 五、建议的最小改动路径

**不要**继续让 LLM 自由生成整场 HTML。`scene-contract.ts` 里那一串禁用规则（禁定时器、禁随机数、禁网络请求），本质是在给自由生成的代码打补丁，稳定性不可控。

改成三层：

```
copy 阶段：主题 → 结构骨架 → scenes[].shots[]（一句一镜，每镜 2–4 秒）
scene 阶段：shots[] → 选择组件模板 + 填参数（LLM 只做选型和填参，不写裸 HTML）
render 阶段：cue 驱动逐帧，动效固定时长，不随场景拉长
```

附带收益：scene 阶段失败率下降、渲染不确定性下降、风格漂移收敛，审核点也能从"看整场动画"细化到"看单个镜头"。

---

## 六、已经正确、不要改的部分

- HTML + GSAP + Playwright 确定性寻帧——实现"排版型动效"最省成本的路线，比把 AE 工程化强得多
- 逐帧 JPEG q92 的性能取舍（相比 PNG 快 3–4 倍）
- 七阶段能力注册表 + 断点续跑 + 三级 trace（run_stages / tool_calls / llm_calls）
- 竖屏 / 横屏双 Profile，与参考片的 16:9 横屏一致

---

## 七、下一步建议

按依赖顺序做最小闭环：

1. copy 契约加 `shots[]`，文案提示词改为"一句一镜"
2. TTS 加时间戳（或 ASR 对齐），产出 `cues[]`
3. 先实现 3 个组件（关键词块 / 数据卡 / 引语卡），覆盖参考片 70% 的画面
4. 字幕独立成 ASS 轨烧录
5. 动效时长改为固定值

完成这 5 步，就能从"PPT 感"跨到"参考片质感"。
