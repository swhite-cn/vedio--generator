## 一、结论摘要

《差距分析》的结论是"方向对、粒度错"。落到架构上，这句话可以进一步收敛为三个判断：

1. **当前架构把"镜头"和"场景"合成了一层**。`copy.json` 的最小单位是 `scene`，而 `scene` 同时承担了口播段落、配图单位、动画单位、时间轴单位、审核单位五种角色。参考片的粒度要求这五种角色必须解耦，核心动作是**在 copy 契约里新增 `shot` 层**，并让下游各阶段改按 `shot` 定位。
2. **当前架构把"视觉"交给了 LLM 现编代码**。`scene` 阶段产出的是整场 HTML/CSS/JS，`scene-contract.ts` 里那一长串禁用规则本质上是对自由生成代码的补丁。要做的不是继续加禁用规则，而是**把视觉产物从"代码"换成"组件选型 + 参数"**，把确定性收回到 `template-sdk` 手里。
3. **当前架构的时间模型只有"音频时长"一个变量**。`timeline.json` 只有场景级 `startMs/endMs`，渲染按比例把固定时长动画拉伸到实际时长，字幕只能整段塞进场景 HTML。要补的是**句级 cue 时间轴 + 独立字幕轨 + 固定动效时长**这一组时序基础设施。

这三件事分别对应数据契约层、模板与视觉层、时序与渲染层，彼此有严格依赖：**没有 shot 层就没有 cue 的挂载点，没有 cue 就没有逐句字幕，没有组件库就无法做固定时长动效**。

改造完成后，架构上最大的收益不是"更好看"，而是：

- `scene` 阶段从"生成可执行代码"退化为"结构化选型"，失败率和风格漂移同时下降；
- 审核点可以从"看整场 15 秒动画"细化到"看单镜头 3 秒"；
- 渲染、字幕、音频、质检都能按 `shot` 切片并行与复用，为后续成本优化留出结构位置。

## 二、现状架构基线

### 2.1 分层与职责（当前）

| 层 | 位置 | 当前职责 | 关键事实 |
|---|---|---|---|
| 契约层 | `packages/pipeline/src/copy-contract.ts` | 定义 `CopyDoc / CopyScene` | 最小单位是 `scene`；`imagePath/audioPath/htmlPath` 由下游回填；无 `shot`、无来源字段 |
| 能力与阶段层 | `apps/server/src/workflow/capabilities.ts`、`packages/shared` | 七阶段线性声明 + 产物判据 + 审核点 | `reviewGates = ["copy","image"]`；判据只到"文件存在 / glob 数量 / JSON 可解析" |
| 阶段工具层 | `apps/server/src/agent/tools/stage-tools.ts` | 七个阶段工具的入参 schema 与执行 | 范围参数是 `sceneIds`；`composeSpec` 未暴露 bgm；路径由 `StageToolContext` 注入 |
| 生成能力层 | `packages/pipeline/src/*` | copy/image/scene/tts/storyboard/compose 的实现 | image 逐场景一图、无参考图/seed；tts 无时间戳；storyboard 只有场景级时间轴 |
| 模板层 | `packages/template-sdk` | 场景契约、内置动画模板、Profile、GSAP 供应商 | `SceneData` 只有 `sceneId/title/narration/imagePath/htmlPath`；降级模板固定 10 秒 |
| 渲染层 | `packages/renderer/src/*` | Playwright 多页轮转逐帧截图 | `progress = 帧时刻 / 场景时长`，再 `seek(progress × 时间轴时长)` |
| 合成层 | `packages/pipeline/src/compose*.ts` | 音频拼接 + 帧序列合成 | 支持 bgm 但未被阶段工具暴露；无 loudnorm、无音效、无字幕轨 |
| 留痕层 | `apps/server/src/trace`、`packages/pipeline/src/manifest.ts` | 三级 trace + 生成清单 | 阶段粒度留痕；无镜头级留痕与镜头级审核记录 |

### 2.2 当前数据流（架构视角）

```
copy(JSON: scenes[]) → image(每 scene 一图) → scene(每 scene 一段 HTML)
      → tts(每 scene 一段音频) → storyboard(scene 级 start/end) → render(逐帧拉长时间轴) → compose(帧+音轨)
```

三个隐含假设贯穿全链路：
- **假设 A：一场景 = 一镜**。这个假设同时体现在契约、工具入参、时间轴、渲染、审核五个位置。
- **假设 B：视觉产物是可执行代码**。因此需要一堆白名单/黑名单治理，且无法跨场景复用样式。
- **假设 C：画面节奏由音频长度决定**。因此动画时长只能被动拉伸，且没有任何"此刻该发生什么"的表达能力。

## 三、差距 → 架构缺口映射

| 《差距分析》差距项 | 当前架构原因 | 缺口所在层 | 变更性质 |
|---|---|---|---|
| 分镜粒度（3.7 秒/镜 vs 9–18 秒/场） | 假设 A | 契约层 + 阶段工具范围参数 + 能力判据 | **破坏性扩展**（契约升版） |
| 字幕无逐句时间戳 | 假设 C + TTS 无时间信息 | 时序层 + 合成层 | 新增能力 |
| 版式只有底图+标题+字幕条 | 假设 B | 模板层 + scene 阶段职责 | **范式替换** |
| 素材类型单一 | 契约里只有 `imagePath` | 契约层 + 资产层 | 扩展 |
| 动效被拉伸（隐藏致命点 1） | 假设 C + 渲染寻帧映射方式 | 渲染层 | 替换寻帧模型 |
| 风格无法跨镜头一致（隐藏致命点 2） | 无主题层、无资产复用、无风格锚 | 主题层 + 模板层 + 图像生成层 | 新增 |
| 无来源/免责表达 | 契约无字段、组件无对应版式 | 契约层 + 模板层 + 质检层 | 新增 |
| BGM 未暴露、无响度/音效 | 阶段工具参数裁剪 + 合成链不完整 | 合成层 + 阶段工具层 | 扩展 |
| 质检门禁缺失 | 产物判据只判断"存在" | 质量层 + 能力判据 | 新增 |
| 审核点粒度粗 | 审核只挂在 copy/image 两阶段 | 审核模型 + 工作台 | 扩展（涉及持久化决策） |

> 注：《差距分析》中"引擎支持 BGM 但工具未暴露"已核对属实——`composeVideo` 支持 bgm 参数，但 `composeSpec` 的入参 schema 只有 `profile`。

## 四、目标架构

### 4.1 核心范式转变

```
现状：主题 → LLM 写整场 HTML → 按比例拉伸 → 合成
目标：主题 → 结构骨架 + shots[] → 组件选型与填参 → cue 驱动固定动效寻帧 → 字幕/音频/画面合成
```

三条不变的原则（避免改造走偏）：

- 渲染运行时切换到 **Remotion（React 帧驱动渲染）**，替代自研 HTML/GSAP 寻帧 + Playwright 截图；ffmpeg 保留为响度归一与特殊封装的兜底。不引入 AE、不做时间轴 GUI 优先、不做云端渲染。决策依据与验证结果见 **附录 C**。
- 继续保留 **七阶段 + 能力注册表 + 断点续跑 + 三级 trace** 的骨架。改造是扩展阶段职责，不是推翻流水线。
- 继续坚持 **LLM 不直接决定写盘路径、不直接产出不可审计的执行体** 这条安全边界。

> 引擎决策更新（2026-11-02）：Remotion PoC 已在本机跑通（双镜头 / 中文 / 音轨 / 单帧 / 帧区间重渲）。W3、W4、W9、W10 中"自研模板层 / 自研寻帧 / 自研帧序列编排"的实现路径改由 Remotion 承担；W1、W2（契约与时序）、W11（字幕）、W14（质检）、W15（能力层）不变。

### 4.2 分层职责重划

| 层 | 改造后职责 | 明确不负责 |
|---|---|---|
| 契约层 | 承载 `scenes[].shots[]`、cue、组件引用、主题引用、来源字段；是全部下游阶段的唯一输入真相 | 不承载渲染细节、不承载组件实现 |
| 编排层（storyboard） | 把"音频时长"升级为"句级 cue 时间轴 + 镜头切点 + 动效触发点" | 不做像素、不做字幕排版 |
| 模板层（template-sdk） | 组件库 + 组件注册表 + 主题解析 + 场景文档装配；对渲染层输出确定性时间轴 | 不调用 LLM、不做内容决策 |
| 渲染层 | 按镜头渲染、按 cue 寻帧、动效固定时长、支持帧复用 | 不解析文案语义 |
| 合成层 | 画面 + 旁白 + 字幕轨 + BGM/音效 + 响度归一 | 不做内容生成 |
| 质量层 | 静帧/溢出/遮挡/对比度/来源完整性等可判定检查 | 不做主观审美判断 |
| 能力层 | 阶段声明、产物判据、审核点、参数契约随之扩展 | 不内置阶段专有业务知识 |

### 4.3 数据契约的三层演进

这是整份文档里**唯一必须最先落地**的部分，其余工作都挂在它上面。

- **第一层：CopyDoc（内容层）**
  `scenes[]` 保留为"叙事段落/章节"概念，新增 `shots[]` 作为最小视觉单位。每个 shot 至少需要表达：本镜口播、屏上文字、视觉类型、素材引用、组件引用与参数、转场意图、来源/免责信息。`scene` 从"渲染单位"降级为"叙事分组 + 章节点"。
- **第二层：TimelineDoc / CueDoc（时序层）**
  从"`sceneId + start/end`"升级为"shot 切点 + 句级 cue（start/end/text）+ 动效触发点"。cue 是字幕、动效、审核定位共同的时间索引。
- **第三层：SceneSpec（视觉层）**
  从"HTML 字符串"换成"组件 ID + 参数 + 主题 + 资产引用"的结构化规格。HTML 由模板层装配，不再是 LLM 产物。

契约变更必须**版本化**：`copy.json` 升版并保留旧版读取能力，才能让存量项目继续续跑（见第六节迁移策略）。

### 4.4 时序模型

- **动效时长固定**：单个动效是 0.3–0.8 秒的常量，与镜头时长无关；镜头时长只决定"停留多久"，不决定"动画多快"。
- **cue 驱动**：镜头内的"关键词上屏 / 下划线扫入 / 数字滚动 / 数据卡入场"由 cue 触发，而不是由线性进度插值。
- **切点由旁白决定、由 shot 显式声明**：shot 边界以句级时间戳为准，允许在句间留白处切；不要求"一句必须一镜"，但要求"每个 shot 有明确起止"。
- **尾部/章节停顿** 作为时间轴的一等公民（当前是硬编码常量），应进入配置或契约。

### 4.5 字幕与音频

- 字幕从场景 HTML 中**整体剥离**，成为独立轨道，在合成阶段烧录（方案选型见第六节决策点）。
- 字幕样式（字号、描边、底部安全距离、单行字数上限）进入主题 token，而不是散落在模板里。
- 音频链补齐：BGM 暴露到阶段工具、音效层、整体响度归一、旁白与 BGM 的自动闪避（ducking）。

### 4.6 视觉一致性

一致性靠三件事，缺一不可：

- **主题 token**：配色、字体、安全区、描边、圆角、间距作为一套可切换的主题配置；与"画幅 Profile"解耦（Profile 管分辨率与安全区比例，主题管视觉语言）。
- **组件库**：把参考片里的版式（数据卡、引语卡、对比条、进度环、章节角标、来源标签、关键词块）做成参数化组件，并登记到组件注册表，供 `scene` 阶段选型。
- **资产复用与风格锚**：同一符号（如"质子=红球"）在多镜头复用同一份资产；文生图增加参考图/固定 seed/统一风格前缀的能力位，图像生成层需支持"资产引用"而非"每镜新生成"。

### 4.7 质量与审核

- 产物判据从"文件存在"升级为"结构可校验"：shot 必填字段齐全、cue 覆盖全部口播、每个数据类 shot 带来源标签。
- 新增质检门禁：连续静帧检测、字幕溢出/遮挡、前景背景对比度、来源完整性。
- 审核点从"整场动画"细化为"镜级别"，但这会带来审核记录持久化的问题，属于需要拍板的架构决策（见第六节）。

## 五、工作项清单

按层分组，编号供后续拆分任务使用。每项给出"架构动作 / 主要影响面 / 架构级验收标准"，不写实现。

### A. 数据契约层

**W1 copy 契约引入 shot 层**
- 架构动作：`CopyDoc` 升版，`scenes[].shots[]` 成为最小视觉单位；明确 scene 与 shot 的职责边界；定义 shot 的必填语义（口播、屏上文字、视觉类型、组件引用、素材引用、转场意图、来源信息）。
- 影响面：copy 契约、copy 提示词集、image/scene/tts/storyboard 的输入解析、阶段工具范围参数、能力产物判据、前端工作台数据展示。
- 验收标准：任意新项目产出的 copy 文档，能在不读提示词、不读代码的前提下，按 shot 枚举全片画面变化；旧版 copy 文档仍可被读取（兼容读取）。
- 依赖：无（本项是所有后续工作的前置）。

**W2 时间轴契约升级为 cue 层**
- 架构动作：新增/升级时间轴契约，从"场景起止"扩展为"shot 切点 + 句级 cue + 动效触发点"；确定时间戳来源策略与降级路径（原生时间戳 / ASR 对齐 / 按字速估算），并把"来源"写进契约，避免下游无法判断精度。
- 影响面：ark 客户端、tts 能力、storyboard 能力、渲染层、字幕、审核定位。
- 验收标准：任一 shot 内全部口播句都有 start/end；时间戳来源在产物中可追溯；精度不足时能被质检识别为降级而不是静默通过。
- 依赖：W1。

**W3 视觉规格契约替换"HTML 即产物"**
- 架构动作：定义结构化的 `SceneSpec`（组件 ID + 参数 + 主题 + 资产引用），作为 scene 阶段产物与渲染层输入；HTML 降级为"装配结果"而非"源头产物"；保留旧 `htmlPath` 通道作为兼容与兜底。
- 影响面：scene 契约、scene 提示词集、scene 阶段工具、模板层、渲染层、断点续跑的产物判据。
- 验收标准：正常情况下渲染层只消费结构化规格；任一规格无法装配时，走显式兜底而不是静默失败；产物判据能区分"规格合法"与"装配成功"。
- 依赖：W1、W4（没有组件库则规格无处落）。

### B. 模板与视觉层

**W4 版式组件库与组件注册表**
- 架构动作：在 `template-sdk` 内建立组件注册表（组件 ID、参数 schema、适用画幅/主题、动效契约），先覆盖参考片高频版式；组件只接受参数，不接受任意 HTML；组件必须满足确定性约束（无定时器、无随机、无网络）。
- 影响面：模板层、scene 提示词集（从"写代码"改为"选型填参"）、scene 阶段工具、渲染层、审核与预览。
- 验收标准：参考片 70% 以上画面可用现有组件表达；新增一个组件不需要改流水线代码；组件使用错误参数时在装配期报错而非渲染期崩。
- 依赖：W3。

**W5 主题 token 体系**
- 架构动作：新增主题配置层（`config/` 下主题目录），定义色板、字体、安全区、描边、间距等 token；主题与 Profile 解耦；明确主题如何进入场景装配与字幕样式。
- 影响面：配置层、模板层、渲染层、字幕、前端预览、项目创建参数。
- 验收标准：切换主题不需要改任何组件代码；同一主题下所有镜头与字幕的视觉参数同源；主题缺失时有明确报错而非回退到硬编码。
- 依赖：W4（弱依赖，可与 W4 并行）。

**W6 素材类型与资产引用模型**
- 架构动作：在契约中把"一张图"扩展为"资产引用"（类型 + 引用 ID + 用途），至少覆盖生成图、上传实拍、档案照片、渲染图、符号化图形；定义资产解析与缺失处理；与项目资产图谱设计线的 `project_assets` 在"引用格式"上对齐，但**不把本工作项并入资产图谱线**。
- 影响面：契约层、image 能力、渲染层、上传路径、前端工作台。
- 验收标准：同一个符号资产可被多个 shot 复用；资产缺失时能定位到具体 shot；上传与生成两类资产在契约中同构。
- 依赖：W1；与资产图谱设计线存在接口级协作。

**W7 转场层**
- 架构动作：把转场从"实现细节"提升为契约字段（硬切 / 字卡 / 短淡化），并定义其与 cue、与镜头切点的关系；明确转场由渲染层还是合成层实现（架构决策，见第六节）。
- 影响面：契约层、渲染层、合成层、模板层。
- 验收标准：转场类型可枚举、可校验；默认硬切不需要额外配置；转场不破坏确定性寻帧。
- 依赖：W1、W2。

**W8 风格一致性机制（文生图层）**
- 架构动作：图像生成能力增加参考图、固定 seed、统一风格前缀、负面描述的能力位；确立"元素资产表"复用策略；明确哪些镜头允许新生成、哪些必须复用资产。
- 影响面：image 能力、ark 客户端、prompt 集、契约（风格锚引用）、manifest 记录。
- 验收标准：同一项目内同一符号的多镜头画面可追溯到同一资产/同一 seed；风格参数变更可审计。
- 依赖：W6。

### C. 时序与渲染层

**W9 动效时长解耦与 cue 驱动寻帧**
- 架构动作：替换"按进度比例拉伸时间轴"的寻帧模型，改为"当前时刻 → 查到 cue → 固定动效时长 → 计算动画进度"；镜头尾部停留不改变动效速度；同时明确"无 cue 时的默认行为"。
- 影响面：渲染层、模板层、时间轴契约、降级模板。
- 验收标准：同一动效在 3 秒镜头与 6 秒镜头中的播放速度一致；修改旁白长度不改变动效观感；无 cue 的旧项目仍能渲染（兼容路径）。
- 依赖：W2、W3、W4。

**W10 镜头级渲染与帧复用**
- 架构动作：渲染单位从 scene 下沉到 shot，保留全局帧号连续；引入"静止段复用帧"的能力位；明确帧命名与分片并发策略在新单位下的约束。
- 影响面：渲染层、渲染编排、合成层（帧序列约定）、成本与耗时。
- 验收标准：按 shot 渲染产出的帧序列与按 scene 渲染的帧数、帧序号一致；复用帧不影响最终成片时长；分片并发仍保持全局连续。
- 依赖：W1、W9。

### D. 音频与合成层

**W11 独立字幕轨**
- 架构动作：字幕成为独立产物（轨道文件），由 cue 生成；字幕样式取自主题 token；合成阶段负责烧录；场景组件不再承担字幕。
- 影响面：storyboard/compose 能力、模板层（移除字幕条职责）、主题、质量门禁（溢出检测）、渲染层（不再渲染字幕）。
- 验收标准：字幕时间与 cue 一一对应；关闭字幕不影响画面渲染结果；字幕样式改动不触碰组件。
- 依赖：W2、W5；与 W9 有并行关系。

**W12 音频链补齐**
- 架构动作：BGM 暴露到阶段工具与项目参数；新增音效层、整体响度归一、旁白/ BGM 自动闪避；明确音频链在合成阶段的顺序与开关。
- 影响面：合成能力、阶段工具参数、配置层、质量门禁（响度检查）。
- 验收标准：BGM 可通过参数启用/禁用；响度目标可配置；无 BGM 时行为与现状一致。
- 依赖：W11（同属合成阶段重构，建议同批）。

### E. 可信度与文案结构

**W13 来源与免责的契约化**
- 架构动作：契约中增加来源引用与免责表达的字段；提供对应的版式组件（来源标签）；质检增加"数据类 shot 必须有来源"的规则；文案提示词集增加结构约束（钩子/结论前置/设问/降温/免责/回环）。
- 影响面：契约层、组件库、提示词集、质检门禁、审核界面。
- 验收标准：来源信息能从契约一路带到成片；缺失来源可被质检拦截；提示词集切换不影响契约结构。
- 依赖：W1、W4。

### F. 质量、能力与工程层

**W14 质检门禁**
- 架构动作：新增可判定的质量检查（静帧、字幕溢出/遮挡、对比度、来源完整性、cue 覆盖率），并定义其产物（质量结论）与 run 的关系；明确"警告"与"阻断"的边界，避免门禁变成不可用。
- 影响面：能力产物判据、工作流引擎（阶段结束时执行）、trace（结论留痕）、审核界面。
- 验收标准：每项检查可独立开关、可复现、有明确输入产物；阻断型检查失败时 run 状态与错误码语义清晰。
- 依赖：W2、W11、W13。

**W15 能力注册表与产物判据扩展**
- 架构动作：阶段声明随契约升级（产物判据从"存在/数量"扩展到"结构可校验"）；阶段工具范围参数从 `sceneIds` 扩展到 `shotIds`（并保留按 scene 批量语义）；新增产物类型（字幕轨、质量结论、主题解析结果）的登记方式。
- 影响面：`packages/shared` 能力类型、`capabilities.ts`、阶段工具、断点续跑、前端能力视图。
- 验收标准：新产物类型能被断点续跑正确判定；按 shot 定向重生成不触发整片重跑；能力视图仍能完整表达阶段与产物。
- 依赖：W1、W3、W11、W14（分批落地）。

**W16 审核点与可观测性演进**
- 架构动作：审核从"阶段级 copy/image"扩展到"镜头级复核"；确定镜头级审核结果是否需要持久化（涉及是否新增表）；trace 与 manifest 增加 shot/cue 维度的定位信息；审核界面从"整场动画预览"演进为"镜头列表 + 单镜预览"。
- 影响面：审核模型、数据库（视决策而定）、trace、工作台页面、SSE 事件。
- 验收标准：任一镜头可被单独定位、预览、重生成；审核结论与镜头一一对应且不覆盖历史；不新增表时要有明确的替代落点。
- 依赖：W15、W10。

**W17 迁移与兼容层**
- 架构动作：定义契约版本识别、旧项目续跑策略、旧 `htmlPath` 通道的保留范围、双轨期的降级与告警；明确"哪些存量项目必须重建、哪些可以续跑"。
- 影响面：契约读取、断点续跑、阶段工具、manifest、前端展示。
- 验收标准：旧版 copy 文档在未重跑 copy 的情况下，至少能完成 storyboard→compose 的续跑（或给出可执行的明确提示）；契约版本在 trace 中可追溯。
- 依赖：W1、W3；应贯穿 A/B/C/D 各批次，而不是最后补。

### G. P2 规模化（暂不进入本轮）

**W18 分镜时间轴编辑器**（工作台侧的镜头级可视化调整）
**W19 2.5D 视差**（图片分层 + 摄像机位移，属模板/渲染能力）

## 九、边界与不做

- **不换产品形态，但换渲染运行时**：视觉运行时切到 Remotion（见附录 C），ffmpeg 保留用于响度/封装兜底；不做 AE 工程化、不做时间轴 GUI 优先、不做云端渲染。
- **不改变部署与安全边界**：仍是 127.0.0.1 本机单进程；不因新增产物类型放宽写盘路径约束。
- **不与项目资产图谱设计线合并**：资产图谱解决"项目内有哪些资产、谁引用了它、agent 做了什么动作"；本清单解决"镜头怎么表达、怎么渲染、怎么合成"。两者只在资产引用格式上对齐。
- **不在本文展开实现**：字段级 schema、函数签名、Prompt 全文、ffmpeg 参数、组件具体实现均留给后续设计文档。
- **不承诺未验证能力**：真实 Ark 端到端验收尚未完成，本文所有判断均基于代码事实与《差距分析》，不代表对应能力已可用。

## 附录 B：术语

| 术语 | 含义 |
|---|---|
| scene | 叙事段落/章节，可包含多个 shot；不再是渲染最小单位 |
| shot | 最小视觉单位，一句或数句口播对应一个镜头，2–4 秒量级 |
| cue | 时间轴上的句级/事件级定位（start/end/text 或动效触发点） |
| 组件（component） | 参数化的版式模板，由模板层装配为确定性场景文档 |
| 主题（theme） | 一套视觉 token（色板/字体/安全区/描边等），与画幅 Profile 解耦 |
| 资产引用（assetRef） | shot 对项目内资产的结构化引用，替代裸 `imagePath` |
| 契约版本 | copy / timeline 文档的版本标识，用于兼容读取与迁移 |

| 帧区间 | `renderFrames [90,119]` 输出 30 张，镜头内动画从相对 0 帧开始 |
| 耗时 | bundle 1.4s（缓存命中）/ `renderMedia` 22.4s / 全流程 28.3s |
| 素材路径 | `staticFile` + `public` 目录在 Windows 路径下可用 |

### C.3 实测约束（必须进入实施规范）

1. **只能渲染 production bundle**。强制 webpack `mode: "development"` 会产出全白帧（React 子树不挂载），不能用来调试画面。
2. **Chrome Headless Shell 下载在本网络失败**（`remotion.media` 20s 无数据 / ECONNRESET）。落地时必须提供"复用本机 Chrome"的配置项（PoC 用 `browserExecutable` 指向 `C:\Program Files\Google\Chrome\Application\chrome.exe`），并在下载失败时给出可操作的错误提示。
3. **缺失/未导出组件在生产构建只报 React #130**（Element type is invalid），定位成本极高。引擎包必须加"依赖 undefined"守卫或构建期检查。
4. `Series` / `Series.Sequence` 当前版本可用，但 `Sequence + 绝对 from` 与本项目 cue 时间轴更同构，**优先用 `Sequence`**。
5. React 与 Remotion 的组合需锁定版本；PoC 已验证 React 19.3.1 + Remotion 4.0.540 可用。

| 项 | 说明 |
|---|---|

### C.7 架构级验收判据

- 同一份 `shots[]` 输入，Remotion 成片的时长、镜头切点、音轨、字幕与契约一致。
- 单镜头重渲不触发整片重跑，且重渲结果与整片对应区间逐帧一致（确定性）。
- 旧项目（`htmlPath`）可续跑，或给出明确、可执行的迁移提示，不静默失败。
- 渲染失败能定位到"哪个镜头、哪个组件、哪个依赖"，而不是只剩 React #130。
- 停用 Remotion 回退到旧引擎时，契约与产物命名不破坏断点续跑。
